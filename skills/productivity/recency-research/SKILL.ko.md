# Recency Research (최근성 리서치)

"지금 사람들이 X에 대해 *실제로* 뭐라고 하나?" 에 답한다 — 모델 기억이나 SEO 블로그가 아니라 최근 커뮤니티 신호에 근거해서. 가치는 깊이(실제 인용, 실제 인게이지먼트 숫자, 소스 간 교차 확인)지 링크 덤프가 아니다.

**맞는 경우:** *최근 ~30일*의 진실이 필요한 인물/회사/제품/툴/주제. **아닌 경우:** 상시적 사실이나 하우투(`document-with-research` 사용); 코드베이스 질문.

## 먼저 역량 확인

이 스킬은 현재 에이전트가 가진 웹/검색 도구로 돈다. 시작 전:

- **완전한 엔진이 있나?** upstream `last30days` 툴이 설치돼 있으면(머신에 `last30days.py`, 또는 `/last30days` 명령) 그걸 우선하라 — 이 워크플로가 못 닿는 API 키 소스(TikTok, Instagram, Polymarket, LinkedIn), 저장 라이브러리, 워치리스트를 더한다. 빠르게 확인: 호스트가 슬래시 명령을 지원하면 `/last30days` 를 시도, 아니면 `command -v last30days || ls last30days.py 2>/dev/null`; 아무것도 없으면 아래 경량 워크플로로 진행. 거기로 넘기고 여기서 멈춰라.
- **아니면**, 아래 경량 워크플로를 호스트의 웹 검색/페치 도구로 돌려라. 커버리지를 정직하게: 플랫폼 API 없이는 Reddit, HN, GitHub, 일반 웹은 안정적으로, X/YouTube/TikTok은 공개 웹 검색에 노출되는 만큼만 얻는다. 그렇게 말하라 — 못 닿은 소스를 검색한 척 절대 하지 마라.

## 워크플로

### 1. 누가/무엇이 중요한지 해소
검색 전에 엔티티를 해소해 쿼리가 노이즈가 아닌 실제 신호에 맞게:
- 인물 → 핸들(X, GitHub), 등장하는 서브레딧, YouTube 채널.
- 회사/제품 → GitHub org/repo(라이브 스타 수 확인), 서브레딧, 공식 계정.
- 주제 → 그걸로 논쟁하는 커뮤니티(r/…), 올바른 검색 표현.

리터럴 문구("42살 남자 선물")는 아무도 그렇게 안 쓰기 때문에 노이즈를 반환한다. 검색 전에 사람들이 실제로 말하는 방식으로 재구성.

### 2. 닿는 각 소스를 ~30일로 윈도잉해 검색
도구가 허용하면 병렬로. 각각에 대해 제목뿐 아니라 *인게이지먼트 숫자*와 *링크*를 확보:
- **Reddit** — 상위 스레드 + 업보트 수 달린 상위 댓글. 1,500 업보트 스레드가 아무도 안 읽은 블로그보다 무겁다.
- **Hacker News** — 포인트 + 댓글 수; 기술자들이 논쟁하는 곳.
- **GitHub** — 툴이면: 최근 이슈/디스커션, 릴리스 노트, 라이브 스타 수. 인물이면: 최근 PR/repo.
- **웹** — 최근 기사, 단 여러 신호 중 하나지 정답이 아님.
- **X / YouTube** — 공개 웹 검색이 노출하는 만큼만; partial 이라고 라벨.

### 3. 리스트가 아니라 병합
같은 사건이 Reddit·X·블로그에 뜨면 → 별개 3개가 아니라 *하나*의 클러스터. 클러스터를 소스 간 인게이지먼트 + 신선도로 랭크. 높게 점수 나와도 주제 밖 바이럴 노이즈는 버려라.

### 4. 근거 있는 브리프 하나로 종합
구조:
- **What I learned:** — 2–4개 짧은 문단, 각각 구체적 발견으로 시작, 특정 데이터에 근거("r/…에서 569 업보트", "이달 23개 PR 머지").
- **원문·출처 표기 커뮤니티 인용 ≥ 2개를 본문에 엮어라**(`u/name`, `@handle`) 맞는 자리에 인라인 — 날카로운 커뮤니티 한 줄이 각주가 아니라 헤드라인 가치다. 인용이나 URL을 절대 지어내지 마라; URL이 없으면 이름으로만 표기.
- **Key patterns:** — 반복되는 테마의 짧은 번호 목록.
- 읽기 좋게 인용: URL을 링크 텍스트 뒤로 숨기는 호스트에선 `[name](url)` 인라인 링크; 원시 URL을 보여주는 호스트에선 평문 라벨(`per @handle`, `per r/subreddit`)로 URL을 산문 밖에 둬라. 원시 URL 문자열 금지, URL 수프 금지, 말미 "Sources:" 덤프 금지.

### 5. 커버리지를 정직하게 진술
실제로 닿은 소스 vs 못 닿은 소스(API 키 없음 / 도달 불가)를 명시하며 끝내라. "X에 아무것도 없음" 은 실제로 X를 검색했을 때만 참이다; 아니면 "커버 안 됨" 이라고.

## 가드레일
- 최근성이 핵심 — 최근 ~30일 우선; 더 오래된 건 맥락으로만, 그렇게 라벨링.
- 인게이지먼트가 신호 — 숫자로 뒷받침된 주장이 단언보다 낫다.
- 완전함보다 정직 — 빈틈을 명시한 부분적 브리프가 빈틈을 숨긴 자신만만한 것보다 낫다.
